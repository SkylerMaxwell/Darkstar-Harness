NAVIGATION RULES
----------------
1. Choose Core, Renderer, or both from TASK ROUTING before loading source.
2. Search the chosen monolith for a category marker such as "[3200]" or "[9900]".
3. Search an exact logical path such as "backend/runtime/agent-loop.js" or "backend/renderer/send.js".
4. Every logical module is delimited by DARKSTAR_SOURCE_BEGIN / DARKSTAR_SOURCE_END.
5. Physical consolidation does not erase logical ownership or privilege boundaries.
6. Renderer must never import Core internals directly; cross-boundary behavior uses preload/IPC.
7. Update this index whenever either monolith changes line structure.

ARCHITECTURAL INVARIANTS
------------------------
- All harness features are model invariant.
- Historical tool calls are atomic: completed tool/result pair or nonexistent.
- Stop/forced-stop behavior uses one canonical generation cancellation lifecycle.
- Core owns privileged runtime state; Renderer remains sandboxed and unprivileged.
- Model-action authorization is Core-owned; tools may declare risk but cannot grant themselves privileged/self-gated mode.
- Permission review blocks the exact in-flight tool invocation in Core: Allow resumes it transparently; Reject returns only `The user has rejected this command.` to tool context.
- Workflow persistence owns the durable normalized permission level; Core remains the sole execution authority and workflows never persist pending decisions or approval grants.
- Preload is the sole renderer privilege bridge and consumes the canonical Core IPC channel registry.
- Tests/audits consume the actual Core/Renderer logical-source inventory directly; no retired combined Darkstar.js is synthesized.
- No third first-party production JavaScript file should be introduced without an architectural change.
- Rules_For_Agent_Editors.md is the durable engineering contract.
